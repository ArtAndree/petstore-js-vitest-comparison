# Контрольные вопросы

## 1. Для чего предназначены модульные тесты?

Модульные тесты проверяют небольшие части программы изолированно: функцию, класс или модуль. Они помогают быстро находить ошибки в логике и безопасно менять код. В этом проекте используются API-интеграционные проверки, а не чистые модульные тесты.

## 2. Чем отличается Jest от Vitest?

Jest — самостоятельный тестовый раннер с собственными инструментами для моков, покрытия и настройки. Vitest построен на экосистеме Vite, поддерживает похожий API и обычно удобнее в проектах, уже использующих Vite и ES-модули. В проекте тестовые сценарии общие, поэтому сравниваются именно раннеры.

## 3. Что такое параметризация тестов?

Это запуск одного тестового сценария несколько раз с разными входными данными. В Jest и Vitest для этого используется `test.each`. Например, проверка поиска питомца запускается для статусов `available`, `pending` и `sold`.

## 4. Чем интеграционные (API) тесты отличаются от модульных? Для чего нужны моки?

Модульный тест обычно проверяет функцию отдельно от сети и других систем. API-интеграционный тест отправляет HTTP-запрос и проверяет взаимодействие с сервером: код ответа, заголовки и тело. Моки (`jest.fn`, `vi.fn`), Nock и MSW подменяют внешние зависимости, чтобы изолировать тесты, задавать ответы и проверять сценарии ошибок без реального сервера. В этом наборе запросы идут к публичному Petstore.

## 5. Почему проверять тело, статус-код и структуру данных? Почему публичные API могут быть flaky?

Статус показывает результат HTTP-операции, тело — содержимое ответа, а проверка структуры подтверждает, что данные имеют ожидаемые поля и типы. Публичное API может быть flaky из-за сети, задержек, лимитов, параллельных изменений данных, очисток и временных сбоев сервера.

## 6. Как запускаются тесты в Node.js? В какой IDE?

В проекте тесты запускаются командами `npm test` отдельно из папок `jest-tests` и `vitest-tests`. Указанная IDE: **Visual Studio Code**. Если работа выполняется в другой IDE, здесь нужно написать её фактическое название.

## 7. Что общего между Jest и pytest?

Оба умеют находить тесты по соглашениям именования, группировать их, проверять ожидания, параметризовать сценарии, запускать setup/teardown-код и показывать отчёт о результатах.

## 8. В чём преимущества Vitest?

Vitest использует привычный Jest-подобный API, быстро запускает тесты и хорошо интегрируется с Vite, его плагинами и конфигурацией. Это удобно, когда тесты относятся к фронтенд-проекту на Vite.

## 9. Для каких задач может быть интересен встроенный раннер `node:test`?

`node:test` подходит для небольших проектов и библиотек, когда нужно запускать базовые тесты без установки отдельного раннера. Он встроен в Node.js и поддерживает тесты, под-тесты, хуки и асинхронные проверки.
